# Security and privacy

DuoHinge captures desktop pixels to render a local overlay. Treat diagnostic
screenshots, videos, crash reports, and logs as potentially sensitive.

For ordinary bugs, include the macOS version, Mac model, build version, and steps
to reproduce. Never include signing certificates, private keys, permission
databases, or unredacted desktop captures in a public issue.

For a security vulnerability, use the repository's private vulnerability
reporting feature if it is enabled. Otherwise ask the maintainer for a private
contact channel without publishing exploit details or personal data.

Only run builds from a source you trust. Public binaries should be signed and
notarized; local unsigned compilation checks are not public release artifacts.

No security audit or response-time guarantee is implied by this document.
